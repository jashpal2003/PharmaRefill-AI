# RxTriage AI (PharmaRefill AI)

A voice agent and pharmacist cockpit for community pharmacies. Callers phone in to refill prescriptions, check status, synchronize refills, book a consultation or pay a balance. Everything the agent does is rule-based and auditable. Controlled-substance and emergency cases always go to a pharmacist.

> **Demo data only.** The seeded patients are fictional. This is not a certified pharmacy system. Before using it with real patients you need a BAA with every vendor, a licensed drug-knowledge feed, a real PDMP connection and a security review.

## What's real and what's not

| Area | Status |
|---|---|
| Speech-to-text | **Live.** AssemblyAI v3 streaming with drug-name keyterms, plus file transcription with word boost and language detection. |
| Text-to-speech | **Live.** Cartesia Sonic-2 in English and Spanish. The measured latency is in *Analytics*: about 1–3 s per full utterance via `/tts/bytes`. |
| Conversation engine | Deterministic state machine. Checks the ANI (caller phone number) **and** the full date of birth, or full name plus full date of birth. Controlled-substance hard block that understands negation ("I'm not on oxycodone"). Emergency sentinel. English/Spanish. |
| Drug utilization review (DUR) | Seven categories: drug-drug, duplicate therapy, allergy cross-reactivity, drug-disease, Beers criteria, pregnancy, dose range. Built on a **curated demo rule set**; replace it with First Databank, Medi-Span or Lexicomp in production. |
| PDMP / MME | MME is computed from this pharmacy's own controlled-substance records. **No state PDMP connection.** |
| SOAP notes and call audits | Generated by an LLM via the AssemblyAI LLM Gateway (`LLM_MODEL`) from the real transcript. Without an LLM they fall back to a deterministic template built from the record. Always a draft for pharmacist signature. |
| FHIR export | R4 Bundle: Patient, MedicationRequest (RxNorm), AllergyIntolerance, Condition. |
| WER benchmark | **Measured only in `LIVE_AUDIO` mode**, which needs your own clips in `evals/audio/manifest.json`. Otherwise it scores reference transcripts and labels the result as such. |
| Benefit check / formulary | Local demo formulary tables. Connect Surescripts RTPB for real payer responses. |
| Prior authorization | Full board with CMS-0057-F timers, auto-drafted justification and LLM appeal letters. **No ePA submission to payers.** |
| Immunizations | ACIP-based recommendations and pre-screening. Generates HL7 v2.5.1 VXU messages. **Not transmitted** to any state registry (IIS). |
| Inventory / 340B | Lot-level stock, expiry alerts, reorder suggestions based on dispensing velocity, 340B claim routing and a duplicate-discount flag. No wholesaler EDI or DSCSA exchange. |
| SMS | Twilio when configured. Otherwise messages are recorded with status `SIMULATED` and never shown as delivered. |
| Snap-to-Verify | Reads the NDC barcode from the camera or a photo (browser `BarcodeDetector`: Chrome/Edge) and checks it against the patient's prescription. |
| Database | **Supabase Postgres** (`DATABASE_URL`), in a private `rxtriage` schema that the Supabase Data API does not expose. RLS is on for every table, and the `anon`/`authenticated` roles have no grants. SQLite is used only when no `DATABASE_URL` is set (offline dev). |
| Staff login | **Supabase Auth** (email + password). The backend checks each token against the project's JWKS. The role comes from `app_metadata.rxtriage_role`, which only the secret key can set. |
| Security | Role-bound bearer tokens (admin / pharmacist / technician / intern) with role-based access control. PHI is masked for technicians and interns. Append-only HIPAA access log enforced by database triggers, with breach heuristics. CORS allowlist. |
| Telephony | FastAPI WebSocket PCM stream (`/ws/call/{id}`). No SIP/PSTN carrier integration and no LiveKit. |

## Features by screen

- **Live Voice & Triage:** soft-phone simulator, live transcript, call queue with priority routing (urgent > high adherence risk > known > routine), callbacks, after-hours detection.
- **Warm transfer screen pop:** on escalation the pharmacist gets the transcript, verification status, active prescriptions, allergies, top DUR alerts and adherence score.
- **Patients:** adherence risk (proportion of days covered, PQA method), DUR alerts with mandatory-rationale overrides, benefit check tiers, one-click generic substitution that respects DAW codes.
- **Analytics:** AI containment, average handle time, per-stage latency and p95, intents, escalations, Star-rating adherence proxies, MTM revenue.
- **Prior Authorizations, Immunizations, Proactive Outreach** (opt-out enforced), **Inventory & 340B**, **HIPAA & Compliance** (access log, retrospective DUR, SDOH screening exported as FHIR Observation).

## Setup

```bash
pip install -r requirements.txt
cd frontend && npm install && cd ..

cp .env.example .env                         # AssemblyAI / Cartesia keys + Supabase DATABASE_URL and keys
cp frontend/.env.example frontend/.env.local # NEXT_PUBLIC_SUPABASE_URL + publishable key

python scripts/create_staff_user.py you@pharmacy.com admin --name "Your Name"   # prints a one-time password
python start_all.py                          # backend :8000 (creates schema + demo seed on first start), frontend :3000
```

Sign in at http://localhost:3000. Admins can add staff from the API (`POST /api/admin/staff`) or with the script above. The roles are `admin`, `pharmacist`, `technician` (sees masked PHI) and `intern` (read-only).

To apply the schema by hand instead, run `supabase/migrations/001_rxtriage_schema.sql` in the SQL editor after `create schema rxtriage; set search_path to rxtriage;`.

**Latency note:** each database query costs one network round trip. From India to this project it's about 150 ms, so dashboard views take about 0.5–1.5 s and a voice turn adds about 0.5–1 s. Deploy the backend in the same region as the Supabase project to bring that down to a few milliseconds.

## Regulatory notes

- **Title 21 CFR § 1306:** Schedule II–V refills are never automated; the call is escalated and the order is held for review.
- **HIPAA:** access to patient data is logged; the log cannot be updated or deleted; transcripts are not written to server logs.
- **CMS-0057-F:** PA decision timers are 72 hours for expedited requests and 7 days for standard ones.
- **TCPA:** outreach skips patients who have opted out, and every message carries STOP instructions.
